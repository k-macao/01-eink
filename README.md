# 章鱼 AI.每日研报 · 墨水屏

一个通过 Web Bluetooth 把财经研报显示到电子墨水屏的静态页面。页面内容已从旧的 `001/output/latest.html` 切换为 **`k-macao/007`**，并且只保留四个栏目：

1. **AI 多空概率**
2. **热点话题**
3. **风险点**
4. **机会点**

> 仅供研究参考，不构成投资建议。

## 数据如何更新

```text
k-macao/007（13 源采集器 + 本地情绪模型）
  ↓ 澳门时间 09:10 / 17:10，无凭据采集进程
原始事实快照
  ↓ 当前仓库的可信适配器（可选 DeepSeek 压缩）
data/007-report.json
  ↓ 同源读取、校验、四栏目压缩
js/ai-summary.js
  ↓ Canvas 1bpp 编码 + Web Bluetooth
墨水屏
```

| 环节 | 说明 |
|---|---|
| 来源 | 工作流每次浅克隆 `https://github.com/k-macao/007` 的最新 `main`，直接调用其中的 `pushplus_deepseek.collect_feeds`，不复制或伪造采集结果 |
| 两次更新 | GitHub Actions 使用 UTC `01:10 / 09:10`，对应澳门/香港 `09:10 / 17:10`；分别标记为早报 / 晚报 |
| AI 可选 | 当前仓库配置 `DEEPSEEK_API_KEY` 时，由本仓库的窄接口把事实压缩成四栏目；没有 Key 或接口失败时自动使用 007 本地情绪分与确定性归纳 |
| 凭据隔离 | 可变的 007 代码运行时拿不到 GitHub 写令牌和 AI Key；它退出并保存事实快照后，可信渲染步骤才获得可选 AI Key，发布步骤最后才临时获得写令牌 |
| 页面读取 | 页面只读取同源的 `data/007-report.json`，不在浏览器暴露任何 API Key，也不从旧 `001` 日报抓内容；页面保持打开时每 2 分钟检查报告 id，早晚版次变化后自动重绘预览 |
| 防坏数据 | 空采集会直接失败并保留上一份报告；来源仓库、多空互补、三个列表非空均会校验；错误数据只显示失败提示，不会用空值或旧字段冒充 |
| 初始内容 | 仓库内置的 JSON 来自 007 最近一次成功晚报，第一次自动任务后会由新数据替换 |

### JSON 契约

```json
{
  "title": "章鱼 AI.每日研报",
  "date": "2026-10-24",
  "time": "21:01",
  "edition": "晚报",
  "source": { "repository": "k-macao/007" },
  "probability": { "long": 62, "short": 38, "label": "谨慎乐观" },
  "topics": [{ "text": "热点", "sentiment": "中性观察", "weight": 8.2 }],
  "risks": ["风险点"],
  "opportunities": ["机会线索"]
}
```

页面不会显示 007 的完整长报告、逐源表、券商明细或数据审计，只显示上述四栏。

## 页面使用

1. 使用支持 Web Bluetooth 的浏览器打开页面：桌面 Chrome / Edge、Android Chrome / Edge，或 iOS Bluefy。
2. 点击**连接**并选择墨水屏；旧设备句柄失效时使用**重新选择设备**。
3. 页面会自动读取最新 007 JSON 并显示预览。
4. 点击**推送最新每日研报**，将预览写入设备。
5. 可切换屏幕尺寸、字体、字号、预览倍数、180° 旋转和黑白红三色模式。

### 每天两次自动显示

页面提供两个默认时刻：**09:15 / 17:15**。打开“启用自动推送”后，会在对应时段：

1. 复用用户已经选择过的 `BluetoothDevice` 自动重连；
2. 同步设备时间；
3. 重新读取 `data/007-report.json`；
4. 把早报 / 晚报推到墨水屏。

浏览器安全模型不允许网页在关闭后后台唤起蓝牙，所以自动显示要求：

- 页面保持打开；
- 至少手动选择过一次设备；
- 系统蓝牙与设备保持可用。

浏览器若节流后台标签页定时器，到点后 **10 分钟内**仍会补触发；超过 10 分钟不会误推旧版次。同一日期、同一时段只触发一次，配置和执行标记保存在 `localStorage`。

## 墨水屏排版

| 项 | 说明 |
|---|---|
| 标题 | 固定为用户指定的 **`章鱼 AI.每日研报`** |
| 屏幕尺寸 | 4.2 寸 `400×300`（默认）、2.9 寸 `296×128`、2.13 寸 `250×122` |
| 四栏保留 | 三种尺寸均保留 AI 多空概率 / 热点话题 / 风险点 / 机会点，不因小屏删除末栏 |
| 降级方式 | 每栏预先生成“完整含标注 → 去情绪权重 → 减少条数 → 标点处完整短标题”的候选；放不下时换短版，不把标题或风险句腰斩 |
| 字体 | 黑体加粗（默认）/ 宋体加粗 / 楷体加粗 / 等宽点阵 |
| 字号 | 小 / 标准 / 大；正文硬下限 10px，13px 以下自动取消粗体以免字腔糊死 |
| 二值化 | 1bpp 阈值 176；宽度不是 8 的倍数时行尾补齐位保持白色 |

```bash

  --snapshot snapshot.json \
  --output /tmp/007-report.json \
  --now 2026-10-24T09:10:00+08:00 \
  --no-ai
```

## BLE 图像协议

EPD-nRF5 系列下发顺序：

```text
INIT(0x01) → 等待 → WRITE_IMAGE(0x30, 黑白层)
           → [WRITE_IMAGE(0x30, 红色层)] → REFRESH(0x05)
```

- 报文：`[0x30][flag][data...]`，1bpp、8 像素/字节、MSB first。
- 黑白层 `1=白 / 0=黑`；红色层 `0=红 / 1=非红`。
- 块大小取设备 notification 上报的 `mtu=NNN` 减 2，未上报时默认 240B。
- 固件上报 `rle=1` 时使用位标志编码；否则使用兼容标志。
- 只支持时间同步的固件可能没有 `0x30` 图像写入指令。

## 主要文件

| 文件 | 作用 |
|---|---|
| `index.html` | 蓝牙控制、研报预览、两次自动显示设置 |
