## 快速开始

| 步骤 | 命令 / 配置 | 说明 |
|---|---|---|
| 环境要求 | Python `3.11+`、`requests`、`jieba` | 只生成本地日报无需推送令牌；推送微信需设置 `PUSHPLUS_TOKEN`（本地环境变量或 GitHub Actions 同名 Secret） |
| 进入目录并安装依赖 | `cd /path/to/02 && python3 -m pip install -r requirements.txt` | 安装 HTTP 请求与财经中文分词依赖 |
| 仅生成本地日报 | `python3 output/pipeline.py --no-push` | 采集、分析并生成 HTML 日报，不推送微信 |
| 完整采集与推送流程 | `python3 output/push.py` | 完整流程：采集 → 分析 → 生成 → 新鲜度检查 → 推送 |

| 产物 | 位置 | 用途 |
|---|---|---|
| 最新日报 | `output/latest.html` | 本地查看或推送使用 |
| 日期归档 | `output/daily_report_YYYYMMDD.html` | 按日期保存的完整日报 |
| 量化分析记录 | `output/quant_history.json`、`output/weekly_forecast.json`、`output/hk7_forecast.json` | 记录预测，并在目标交易日后按真实收盘结算 |
| 新闻与情绪记录 | `output/news_history.json`、`output/sentiment_history.json` | 支持跨日去重、政策窗口与情绪基线 |

## 内容口径与阅读提示

| 页面标记 / 数字 | 含义 | 阅读时注意 |
|---|---|---|
| **当天** | 来源内容日期与报告日一致 | 仍需结合栏目本身的统计窗口理解 |
| **非当天 / 滞后** | 内容日期早于报告日，页面会标出日期 | 滞后报价不计入核心指数均值，不应当作实时价格 |
| **今日抓取** | 今天采集到的前瞻日历快照，不代表事件今天已发生 | 不参与“当天内容”推送门禁 |
| **暂缺 / 未展示** | 来源或对应数据块没有可用内容 | 总结的“数据覆盖”会列出暂缺来源；不会用旧数据补位 |
| **概率与回测** | 根据历史数据或明确规则得到的统计结果 | 概率不是保证；样本不足时只报样本量，不下命中率结论 |
| **媒体风险指数（页面 0–100；Agent 0.0–1.0）** | 具体事件严重度、来源权威度、个股归因、跨源 / 跨类确认与新闻量异常的同一序数分；Agent 值仅为页面指数除以 100 | 是同一套规则下的筛查与排序值，**不是事件发生概率或股价涨跌概率**；动作 token 不自动执行，标题只作线索，须回看监管 / 公司原文核实 |
| **栏首 AI 结论 / ⌁ AI 研判依据** | 基于本次页面同栏数据确定性规则合成的辅助说明；先给大白话结论，再列同源概率 / 数字依据与正文 | 是阅读辅助，不是独立数据源，也不是投资建议；证据不足时明确写“不硬判”，不会为补齐栏目编造方向 |
| **↳ 同子栏合并** | 同一批数据只在第一个（或口径更专业的）栏目展开，后出现的栏目保留子栏标题 + 一行指针 | 数字不会少：按指针去对应栏目核对；结论三栏（总结 / 今日预判 / 短线速查卡）仍会复述关键数字 |
| **行情日期核对（`as_of`）** | 行情带对应市场的 `as_of` 日期；若 Yahoo 行情落后，系统用较新的独立行情基准核对 | 不能确认日期更新时不覆盖原值 |
| **资讯与社区边界** | 标题情绪只依据资讯标题，不会从价格涨跌反推新闻观点 | 社区热度与观点未经核实，不等同于事实 |

## 栏目与数据说明

### 阅读版式

| 功能 | 当前规则 |
|---|---|
| 诗与远方的海 | 刊头后的独立卷首栏目，把诗泉诗选与 ☯ 今日卦象放在同一栏内；即使没有行情数据，也可展示卦象。2026-10-16 起**卦象之后紧跟“新手三句话”**（原在速查卡末尾，用户要求「放在卦象后」），入门读者在翻到行情数字之前先拿到看方向 / 放止损 / 别动手三句人话；卦象被 `OCTOPUS_BAGUA=0` 关闭时三句话回落到速查卡末尾，同一份日报只出现一处。微信 / PushPlus 上使用可见图标与直接展开的卦象内容，不依赖点击展开或脚本。诗和卦分别用 `OCTOPUS_SHIQUAN=0`、`OCTOPUS_BAGUA=0` 关闭。 |
| 短线速查卡 | 默认开启，放在今日结论之后作收尾，正文预算 600 字；数字复用本次日报同一批数据。信息过多时按优先级整行收起并说明，避免截断半句话。原先卡尾的“新手三句话”（读取 `output/stock_memes.json` 百句股票梗句库，按当次盘面与种子配对使用）2026-10-16 起移到卷首卦象之后，且不再占用卡片的 600 字预算；卦象关闭时仍排在卡尾。 |
| 全篇精简 | 默认开启；压缩重复长文和样本，但保留结论、关键数字及折叠数量。默认日历看今明与近端重点、个股概率取前 5 + 后 3、新闻源头最多 8 条；`--full` 或 `OCTOPUS_LITE=0` 恢复全量长版，并关闭速查卡。 |

### 策略、情绪与量化分析

| 模块 | 主要口径 | 关键限制 |
|---|---|---|
| 【麻辣大龙虾】散户群体情绪量化分析 | 取本次 Reddit 热帖标题与结构化得分 / 评论数，及 StockTwits 趋势标的、关注人数和平台 Bullish / Bearish 标签；NBI = 100×(看多−看空)/(看多+看空)，分歧熵按多空二元 Shannon 熵缩放到 0–100。 | 只计采集到的样本；标题词表未命中不冒充中性。缺方向标签时指数显示缺值；无 Reddit / StockTwits 样本时整栏缺席。不采集订单簿或小单净买入，不推断微观结构。 |

| 兜底 | 单个行业在东财三台主机都取不到时，逐行业走申万宏源研究所官方指数发布接口；官方源通常滞后一个交易日，滞后行业按「锚点不一致」自动不评分，**同一行业绝不混源**。 |
| 锚点日 | 各行业最后收盘日的众数，必须落在最近完整收盘日；距今超过 14 个自然日 → 整栏缺席（不用过期锚点冒充当日信号）。 |
| 评分 | 近 5 日收益作当周信号；历史 12 个不重叠已结算 5 日窗口算胜率与赔率；零赢或零亏的行业不评分。综合分 = 胜率×80% + [赔率/(1+赔率)]×20%（×100）。20 日 / 60 日收益与 vs MA20 只作背景因子，**不参与排序**。 |
| 月度持仓 | 每月首次成功运行按收盘信号确定前五与目标权重（各自得分 / 前五总分），**下一交易日收盘执行**；当月不随每日评分换仓。 |
| 反馈闭环 | 从执行日收盘起算逐只、组合加权与全行业等权基准表现，超额以 pp 展示；样本只有一个年度周期的一部分，不代表长期有效性。 |
| 判死门槛 | 需 ≥66 根日线才评分；可评分行业少于 max(5, 60%×股票池) = **19** → 整栏缺席（覆盖不足时的「前五」没有意义）。 |
| 诊断留痕与隔离 | 每次运行把诊断写入 `output/news_history.json` 的 `industry_rotation_diag`（跑没跑、复权口径、锚点、覆盖、判死原因）随日报提交；月度持仓存档在 `industry_rotation`，与港股板块轮动的 `sector_rotation*` **互不覆盖** |

## 新鲜度与推送规则

| 场景 | 处理方式 |
|---|---|
| 数据来源回退 | 每条注册的数据线有 1 个主源和 2 个备用源；主源无响应或正文无效时依次回退。实际使用的备用源会记入日志和总结。 |
| 当天内容检查 | 至少一个数据源抓到当天内容，日报才通过默认推送门禁。前瞻日历属于“今日抓取”快照，不能单独打开门禁。 |
| 当天检查未通过 | 默认不推送日报，但会发送纯文本检查告警；需要研究用状态报告时可用 `--allow-incomplete-push`。 |
| 无数据的栏目 | 不显示空栏目，也不拿历史数据冒充实时值；暂缺来源在“数据覆盖”中说明。 |
| 推送可恢复错误 | 网络异常、HTTP 429/5xx 或发送频繁等错误按 10 秒、30 秒、60 秒退避重试，最多 4 次；不可恢复错误立即失败。 |
| 推送仍失败 | 日报发送失败会尝试发送纯文本告警；推送或告警失败以退出码 1 结束，便于 Actions 标红。 |
| 微信推送标题 | 固定为 `[OCTOPUS] 章鱼 AI · 上水日报 - MM/DD HH:MM`（北京时间）；强制推送为 `[OCTOPUS] 章鱼 AI · 上水日报(强制) - …`，状态报告为 `…(状态) - …`，超长分条在末尾追加 ` (i/N)`。2026-10-13 起前缀由 `🐙` 改为 `[OCTOPUS]` 关键词（emoji 在部分微信客户端与转发链路会被裁掉，关键词也能直接用作消息过滤规则）；页面刊头与 `<title>` 仍是不带前缀的「章鱼 AI · 上水日报」，「日报未推送提醒」「日报推送失败提醒」两条告警仍带 🐙。四条推送路径统一走 `build_push_title()`。 |
| 单条内容超限 | 默认上限按 PushPlus 会员 100,000 字符配置；低于上限一页发送，超限则按原 HTML 在栏目 / 完整标签边界拆分，续片重新带栏目头，**不再自动切换成失去 pixel / forum / dossier 等主题的白底纯文字版**。默认最多 12 条、条间 2 秒，并按平台频率限制排队。 |
| 推送对象（一对多 / 一对一） | 2026-10-23 起默认 **一对多群组推送**：群组编码取 `PUSHPLUS_TOPIC`，Actions 里 Secret 缺省时由工作流兜底为群组 `oai.1`，发到该 PushPlus 群组里所有订阅者；本地跑且没配群组编码时日志明确告警并回退一对一（只发给自己），`PUSHPLUS_MODE=one2one` 可显式改回一对一直发自己。分条推送的每一条都走同一路由。 |
| 账号额度与分条开关 | PushPlus 文档列出的会员额度为 10 万字、实名用户为 2 万字，可用 `PUSHPLUS_MAX_CONTENT_CHARS` 覆盖默认值；设置 `PUSHPLUS_MULTIPART=0` 会关闭完整分条，改为安全截断并附完整版链接，磁盘归档仍保留完整报告。 |

### 库文件结构与 AI 数据集

| 层级 / 字段 | 结构内容 | 用途与因果约束 |
|---|---|---|
| 顶层字段 | `schema` (`octopus-market-db/2`)、`db_date` (`YYYY-MM-DD`)、`slots` (`0800` / `1230` / `1700`)、`audit`、`ai` | 单日三档合并存储，`audit` 记录拉取次数与明细，`ai` 保存当天特征与标签摘要 |
| 单档 `slots[slot]` | `pulled_at`、`sources`（含 `standby` 待命标记）、`quotes`（单源报价 + `source` / `is_backup`）、`source_summary`、`fundamentals`、`corporate_actions`、`self_check`、`integrity`（`sha256`） | 完整记录单源报价与主备命中情况、基本面与除权除息、100 分制自检结果及防篡改哈希（读取端兼容历史 `consensus` / `cross_check` 旧快照） |
| AI 特征（无未来函数） | `price`、`change_pct`、`prev_close`、`open/high/low`、`volume/amount`、`spread_pct`、`n_sources`、`confidence`、`n_lagged`、`slot_index`、`ret_prev_slot`、`ret_day_open`、`ret_1d`、`ret_5d`、`vol_5d`、`pe`、`pb`、`total_mv`、`float_mv`、`days_since_action` | `build_dataset()` / `export_dataset()` 只用当次及之前的数据；财务按「当时已知」前向填充（早盘不会拿 17:00 才落库的财务回填） |
| AI 标签与质量标记 | 标签：`next_slot_ret`、`eod_ret`、`next_day_eod_ret`；质量标记：`verdict`、`lagged`、`consensus` | 标签只用之后的数据；`ai_context()` 直接给出最近一档共识价 + 新鲜度 + 自检得分；CI 导出 `output/market_db/ai/dataset.jsonl` 上传为 Actions Artifact |

### 通达信通道（mootdx，2026-10-01 升级）与防卡死四道闸

| 维度 / 闸门 | 做法 | 效果与说明 |
|---|---|---|
| 行情与代码映射 | `Quotes.factory(market='std')` 取沪深实时快照（`quotes()`），在 HTTP 主备源未覆盖沪深标的时作为备用源顶上 | 只对沪深标的生效（如 `600519.SS → sh600519`）；港美股不在通达信标准行情覆盖内 |
| 日K交易日回填 | 启用时取日K（`bars(frequency=9)`）最后一根交易日回填行情时间戳日期部分 | 跳变若由除权除息造成会写明「疑似除权除息」并免于扣分；盘前拉到的上一交易日收盘快照不会被记成当天盘中价 |
| 财务 / 除权除息与降级 | 仅 **17:00 收盘档**抓 `finance()` 与 `xdxr()` 写进 `fundamentals` / `corporate_actions`；主站池默认最多试 4 个（`OCTOPUS_DB_TDX_SERVERS` 可覆盖） | `mootdx` 未安装或全连不上时标记 `unavailable` / `failed`，其余 5 路照常入库；`OCTOPUS_DB_TDX=0` 或 `pull --no-tdx` 可关闭 |
| ① 预置配置 | 建客户端前先写好 `$HOME/.mootdx/config.json`（SERVER 主机池 + BESTIP；`OCTOPUS_DB_TDX_CONFIG` 可换路径）；已存在的配置原样尊重 | 不再出现「未找到配置文件 / 请手动运行 `python -m mootdx bestip`」，也不会写出 `BESTIP=""` 的半残配置 |
| ② TCP 预检 | 先用自己的 socket 探一次（`TDX_PROBE_TIMEOUT`=3s），连不上的站**不交给 mootdx** | 死站 3s 换台，不再进入 tdxpy 重连阶梯 |
| ③ 先验活后明细 | 每台主站先做一次 `quotes()`（全标的、一次调用），行情为空立刻换站；客户端显式 `auto_retry=False` | 一台坏站最多花 1 次调用，而不是 34 次 |
| ④ 总预算 | `TDX_BUDGET_SEC`=90s（`OCTOPUS_DB_TDX_BUDGET` 可覆盖）约束整条通道，到点收工并如实写失败原因 | 单路再坏也不会拖垮作业；其余 5 路照常入库（工作流侧同步加固 `PYTHONUNBUFFERED=1` 与 8 分钟超时兜底，详见 [原因诊断](./通达信通道-作业被取消-原因诊断.md)） |
| 跨源比价补充说明 | 新浪与腾讯的美股字段口径与 A / 港股不同，未纳入比价；Yahoo 对港股 / A 股可能延迟 15 分钟 | 滞后源会被标注并从共识价中剔除，但保留在 `by_source` 明细里；`verify` 会点名被手工改写的日期与档位 |
