## 三、已做的加固（不改变任何判死门槛）

### 1. `output/sector_rotation.py`：取数自愈 + 失败自述

| 改动 | 说明 |
|---|---|
| 行业列表改为**逐页抓取**（每页 100，最多 6 页） | 不再依赖 `pz=500` 是否被接口接受；任一页为空、或抓到的条数 < 接口声明的 `total` → 仍然判定「不完整」并返回空列表（**不用局部行业冒充全行业**） |
| 日线**复权口径自适应** | 先用 1~2 个样本行业探测 `fqt=1 / fqt=0` 哪个能返回日线，再按该口径取全部行业 |
| 探测失败**早停** | 样本行业两种口径都取不到 → 直接判「日K接口未返回数据」，**不对 80+ 个行业逐个重试**（否则网络异常时会把每日任务拖到 15 分钟超时） |
| 失败原因分级 | 5 道门各自给出具体原因与计数（列表个数 / 口径 / 取到日线的行业数 / 锚点日 / 可评分行业数） |
| 诊断**落盘** | 成功与失败都把 `sector_rotation_diag` 写进 `news_history.json`，随日报一起提交 → 隔日可核查 |
| 补齐 Referer | 行情请求带 `Referer: https://quote.eastmoney.com/`；取数函数不接受 `headers` 时自动降级（兼容老式注入） |
| 修掉「成功但栏目消失」的漏洞 | 原逻辑里月度持仓为 `None` 时 `run()` 仍返回 `available=True`，正文整栏静默消失、审计却显示成功；现在这种情况按失败处理并给出原因 |
