## 二、根因（按影响从大到小）

### 根因 1（主因）：Yahoo Chart API 日线在本地 0 点后暂时缺失刚收盘的那一天

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 正文说明 | `fetch_market_snapshot()`、量化引擎 `providers.fetch_bars()`、周度预测 `run_weekly()` 全部走 `query1.finance.yahoo.com/v8/finance/chart/{symbol}?interval=1d&range=…`。Yahoo 的行为是：**交易所本地日期翻篇后，当天那根日线会从 `timestamp/close` 数组里消失，直到日终数据入库（通常本地凌晨 2~4 点）才重新出现**；美股因为时区不同，凌晨 02:56 北京时间时正在盘中，K 线里有实时根，所以美股是"新"的、港股 A股是"旧"的。 |
| 02 | 这是 Yahoo 的已知行为，不是本仓库特有 | yfinance 项目 issue [#890 "No previous day data returned … after UTC midnight for a few hours"](https://github.com/ranaroussi/yfinance/issues/890)（`range=2d&interval=1d` 在本地 0 点后几小时拿不到刚结束那天的 K 线，之后自动恢复）。恒指 / 上证的"本地 0 点"就是北京时间 0 点，正好覆盖 09-29 的 01:54 ~ 02:56 三次运行。 |
| 03 | 正文说明 | 但同一响应的 **`meta` 字段里其实带着正确的收盘**：`regularMarketPrice`（24,642.51）、`regularMarketTime`（09-28 16:08 HKT）、`currentTradingPeriod.regular`（下一个常规交易时段 09-29 09:30–16:00）。修复前的代码完全没有读 `meta`。 |

### 根因 2：代码"取最后两根有效收盘"，从不核对这两根是哪一天

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 正文说明 | 修复前的 `fetch_market_snapshot()`： |
| 02 | 代码/命令 L1 (`python`) | `closes = [c for c in closes if c is not None]` — 去掉空值 |
| 03 | 代码/命令 L2 (`python`) | `price, prev = closes[-1], closes[-2]` — 直接当成"最新"与"前一日" |
| 04 | 代码/命令 L3 (`python`) | `content_dates.append(ts_list[-1] 的日期)` — 日期却取自原始时间戳（含空 K 线） |
| 05 | 代码/命令 L4 (`python`) | `market["content_date"] = max(content_dates)` — 整份快照取最大日期 |
| 06 | 四个后果 | ① 少了一根就悄悄退回上一天，没有任何日志或标注；② 日期取自最后一个时间戳（可能是空 K 线）→ 周一 09:07 标成"当天"；③ 快照日期取全部品种的**最大值**（美股 / WTI）→ 港股 A股滞后被掩盖；④ 各品种没有各自的 `as_of`，页面无从展示。 |

### 根因 3：「核心判断」的指数均值把不同日期的品种混在一起

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 正文说明 | `build_daily_quant_strategy()` 的 `主要指数平均 x%` 是**全部报价**（含 WTI、微软、Meta）涨跌幅的算术平均，不看日期。 |
| 02 | 补充说明 | 09-29 的 -1.24% 是"上周五的 A股港股 + 周一盘中的美股 + 周二电子盘的原油"的平均——一个没有对应任何交易日的数字。 |

### 根因 4：量化引擎与周度预测同源、无回补

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 要点说明 | 量化引擎有"数据倒退"保护（`_is_regression`：本次 as_of 早于留痕最新日则拒绝出结果），所以 02:39 / 02:56 版整栏缺席——**保护起了作用，但结果是整栏消失，读者只看到"暂缺"**。 |
| 02 | 要点说明 | 周度预测没有这层保护，直接"锚定 09-25 收盘"，把上周五当作本周一。 |
| 03 | 要点说明 | 新鲜度检查的阈值（实时行情 3 天、港股量化 4 天）只能拦住"几天没更新"，拦不住"晚一天"。 |

### 根因 5：页面上不写数据日期

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 正文说明 | 「今日预判」的 A股 / 美股 / 港股一句话和核心判断只给数字不给日期，行情速览三个子块也没有日期，只有右上角一个整块徽标（还取自美股日期）。 |
| 02 | **即便数据确实是上一交易日收盘（09 | 00 定时运行时这是必然的：A股港股尚未开盘），读者也应能一眼看到"截至 09-28"**。 |

### 附：不是原因、但相关的两件事

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | **定时任务 09 | 00 北京时间跑**（`cron: 0 1 * * *` UTC）：此时 A股 / 港股还没开盘，「今日预判」里的 A股 / 港股行必然是**上一交易日收盘**，这是"盘前简报"的正常口径，不是 bug——但必须标日期。 |
| 02 | 要点说明 | **`output/weekly_forecast.json` 没有被 CI 提交**（工作流只 `git add` 日报、情绪、新闻、`quant_history.json`），所以周度预测的"留痕 / 结算"每天从零开始，永远积累不出胜率。这需要改 `.github/workflows/octopus-daily.yml`，本次没有改工作流文件，建议在 `git add` 一行加上 `output/weekly_forecast.json`。 |

## 三、修复（三道防线，全部离线可测）

### ① 数据层：用 `meta` 补齐缺失的已收盘日线（三处共用）

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 正文说明 | `output/octopus_quant/providers.py` 新增 `session_bar_from_meta()` / `parse_chart_result()`，`fetch_bars()` 改用它们，`pipeline.fetch_market_snapshot()` 也走同一套解析。规则非常保守，只有**同时**满足以下条件才补一根 `from_meta=True` 的日线： |
| 02 | 要点说明 | `meta.regularMarketPrice` / `regularMarketTime` 存在； |
| 03 | 要点说明 | 按 `meta.gmtoffset` 折算的报价日期 **严格晚于** 最后一根有效 K 线的日期； |
| 04 | 要点说明 | `regularMarketTime` **不在** `currentTradingPeriod.regular` 的 `[start, end)` 之内（即这不是盘中价，而是上一个已结束时段的收盘）；`currentTradingPeriod` 缺失则不补。 |
| 05 | 因此 | 周二凌晨 → 补出周一收盘（对）；周一 09:53 盘中 → 不补（对，盘中价不能当收盘）；meta 也是上周五 → 不补（转入第 ②③ 道防线）。空 K 线（close=null）一律跳过，不再影响日期。 |
| 06 | 正文说明 | 量化引擎和周度预测因此在凌晨也能拿到 09-28 的锚点：量化分析不再"数据倒退"缺席，周度预测不再"锚定 09-25"。 |

### ② 核对层：东方财富独立基准回补

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 要点说明 | `fetch_hk_index_quotes()` 追加请求 `f124`（行情时间），返回 `as_of` / `quote_time`； |
| 02 | 要点说明 | 新增 `pipeline._reconcile_market_snapshot(market, pan, hk_ref)`：A股用「全球大盘全景」（东财 `ulist.np`，带 `quote_time`）核对，港股用东财恒指 / 恒科报价核对。**只有当东财的数据日期严格晚于 Yahoo 的 `as_of` 时才替换**，替换后 `via="eastmoney"`，保留 `yahoo_as_of` 以便审计；来源行改为「Yahoo Finance Chart · 东方财富回补」，品种名后标「（东财）」。东财更旧或同一天不替换；美股 / 商品不动。 |
| 03 | 要点说明 | `collect_all_data()` 在拿到全景之后调用一次。 |

### ③ 呈现层：每个品种带 `as_of`，按市场标日期，滞后品种不入均值

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 要点说明 | 每条报价新增 `as_of` / `prev_date` / `via`（`bar` / `meta` / `eastmoney`）；快照新增 `group_dates`（美股 / A股 / 港股 / 商品 各自日期）、`lagging`（落后于股票市场最新交易日的品种）；`content_date` 改取**股票市场**的最新日期（WTI 电子盘领先一天不再把整块拉成"当天"）。 |
| 02 | 「今日预判」 | A股行写「（截至 09-28 15:00）」（东财全景时间），美股 / 港股行写「（截至 09-28）」，滞后写「（截至 09-25 · 滞后）」，并新增一行「数据提示」说明哪些品种落后、已不计入均值。 |
| 03 | 「核心判断」 | `主要指数平均 x%（截至 09-28[，港股行情滞后未计入]）`，滞后品种**不进均值**。 |
| 04 | 「行情速览」 | 子块标题「全球与美股 · 截至 09-28」「港股双指数 · 截至 09-25 · 滞后」；滞后品种名后加日期，WTI 与子块日期不同也标日期；两套主题（guizang / pixel）一致。 |
| 05 | 控制台日志 | 打印各市场日期、meta 回补了谁、东财回补了谁、仍滞后的品种。 |

## 五、仍需人工决定的事项

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 要点说明 | `.github/workflows/octopus-daily.yml` 的 `git add` 加上 `output/weekly_forecast.json`，否则周度预测留痕不会积累（本次未改工作流）。 |
