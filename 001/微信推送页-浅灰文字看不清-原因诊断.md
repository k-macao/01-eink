## 一、为什么之前改了 `#333` 之后，微信推送页面字体色还是看不清？

### 根因 1（最关键）：PushPlus `v-html` 注入时浏览器按 HTML5 规范直接丢弃 `<body>`，导致正文中 **695 个文本节点（占全篇 39.5%）完全没有任何 `color` 属性**

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 要点说明 | **HTML5 `innerHTML` / `v-html` 片段解析铁律**： |
| 02 | 要点说明 | PushPlus 微信 H5 详情页（`https://www.pushplus.plus/detail.html`）使用 Vue `v-html`（底层即 `element.innerHTML = content`）把推送 HTML 注入到宿主页面的 `<div class="content">` 容器内。 |
| 03 | 要点说明 | 根据 WHATWG HTML5 片段解析规范（`in body` insertion mode），当宿主已经是 `<div>` 时，内嵌 HTML 字符串中的 `<!DOCTYPE>`、`<html>`、`<head>` 与 **`<body ...>` 标签及其所有属性都会被解析器直接忽略并丢弃**。 |
| 04 | 要点说明 | 因此，写在 `<body bgcolor="#FFFFFF" style="...;color:#222;font-size:14px;line-height:1.75">` 上的 `color:#222`、`font-size:14px`、`line-height:1.75` 在微信 PushPlus 页面里**根本不存在**。 |
| 05 | 要点说明 | **PR #87（一页推重构 `da20990`）埋下的无色容器断层**： |
| 06 | 要点说明 | 为压缩单条消息体积，PR #87 把原本写在各容器/表格上的 `color` 全部删掉，只留在了 `<body>` 上；而 `<body>` 内部最外层包裹块写成了： |
| 07 | 代码/命令 L1 (`html`) | `<div style="max-width:680px;margin:0 auto;padding:26px 18px 0;background:` — FFFFFF"> |
| 08 | **它只强制了真白底 `background | #FFFFFF`，却没有写 `color`、`font-size`、`line-height`！** |
| 09 | 要点说明 | 对 `output/latest.html` 全篇 1,761 个文本节点做去 `<body>` 后的 DOM 颜色继承审计（`_BodylessColorAudit`），共有 **695 个文本节点**在 `<body>` 内部没有任何祖先声明 `color`： |

     | 节点路径（剥离 `<body>` 后） | 无 `color` 文本节点数 | 涉及的实际页面内容 |
     |---|---:|---|
     | `div/div/table/tr/td` | **475** | `gz_data_table` 全部数据表正文单元格（行情、全景、量化概率、流动性、日历、审计表；代码注释写明「字号 / 颜色写一次在 `<table>` 上」，实则 `<table>` 漏写了 `color`） |
     | `div/div/div` | **107** | 首屏 26px 核心结论大字、`_gz_news_card` 全部新闻/快讯/政策/趋势标题、每栏末尾「`⌁ AI 研判`」与「`🦑 鲜鲜解读`」正文 |
     | `div/div/div/b` | **61** | 新闻情绪 `▲ S+1`、政策 `▲ +2`、美联储/地缘证据方向标、周度预测标题 |
     | `div/div/table/tr/td/span` | **36** | `octopus_quant/render.py` 个股代码与趋势回归副行 |
     | `div/div/table/tr/td/b` | **14** | 财经日历日期列（`09-29 周二` 等） |
     | `div/div/div/div` | **2** | 策略研判「风险预算」「量化配置」文本框 |

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 要点说明 | **为什么 PR #90 的 `_enforce_dark_gray_font` 没有生效？** |
| 02 | 要点说明 | PR #90 的 `_enforce_dark_gray_font` 仅用正则替换**已存在的** `color:#444~#ddd` 属性： |
| 03 | 代码/命令 L1 (`python`) | `_CSS_COLOR_PROP_RE = re.compile(r'(?<![-\w])(color\s*:\s*)(` — [0-9A-Fa-f]{3,6})\b') |
| 04 | 要点说明 | 上述 695 个文本节点所在的 `<div>`、`<table>`、`<td>` **压根没有写 `color:`**，正则完全不会命中它们！ |
| 05 | 要点说明 | 当微信处于深色模式或 PushPlus 宿主样式将外层容器文字设为浅灰时，这些没有 `color` 的节点直接继承宿主的浅灰文字色，叠在我们强制的 `#FFFFFF` 白底上，变成「白底浅灰字」，彻底看不清。 |

### 根因 2：精简兜底版 `_compact_html_for_push` 同样只把 `color:#111;background:#fff` 写在 `<body>` 上

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 要点说明 | 在 `output/pipeline.py` 的 `_compact_html_for_push` 中，不仅没有内层包裹 `<div>`，而且 `<h1>`、`<h2>`、`<section>`、`<div style="white-space:pre-wrap;...">` 全部未写 `color`（共 173 个文本节点无 `color`），分割线还残留了 `#aaa`。 |
| 02 | 补充说明 | 一旦走精简兜底路径并被 `v-html` 剥离 `<body>`，整篇文字颜色完全裸奔。 |

---

### 根因 3：GitHub Actions 工作流 `git add` 因未生成的选配文件报错退出（Exit Code 128），导致仓库 `output/latest.html` 停留在旧版本

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 要点说明 | `.github/workflows/octopus-daily.yml` 第 107 行此前为： |
| 02 | 代码/命令 L1 (`bash`) | `git add output/daily_report_*.html output/latest.html ... output/hk7_forecast.json output/weekly_forecast.json 2>/dev/null ｜｜ true` |
| 03 | 要点说明 | 当未配置 `OCTOPUS_LLM_API_KEY` 时，`output/hk7_forecast.json` 不会生成；`git add` 遇到不存在的路径会直接报 `fatal: pathspec 'output/hk7_forecast.json' did not match any files`（退出码 128），**整条命令一个文件都不会暂存**，后续 `git diff --cached --quiet` 永远判定为「无新内容，跳过提交」，导致仓库里的 `output/latest.html` 一直停在 `2026-09-29 18:16:24`。 |

## 二、本次彻底修复方案

| 序号 | 维度 / 条目 | 详细内容与说明 |
|---:|---|---|
| 01 | 要点说明 | **全链路容器与表格显式声明内联 `color` + `background:#FFFFFF` + `color-scheme:light`（脱离 `<body>` 后零孤儿节点）**： |
| 02 | 要点说明 | `<head>` 新增 `<meta name="color-scheme" content="light only">`，`<body>` 与最外层 `<div style="max-width:680px;...">` 同步声明 `background:#FFFFFF;color:#222;font-size:14px;line-height:1.75;color-scheme:light;-webkit-text-size-adjust:100%;word-break:break-word;overflow-wrap:break-word;`。 |
| 03 | 要点说明 | `gz_section`（每个栏目容器）、`gz_data_table`（每张 `<table>`）、`_gz_news_card`（每条资讯/研判/鲜鲜解读行）、`gz_shell`、`gz_alert`、`gz_channel_block`、首屏 26px 核心结论 `lead_html`、`_compact_html_for_push` 全部显式带上内联 `color:#222` / `color:#111` 与 `#FFFFFF` 白底。 |
| 04 | 要点说明 | **升级 `_enforce_dark_gray_font()` 双重守卫**： |
| 05 | 第一重 | 继续将任何内联 `color:#444` ~ `#ddd` 浅/中灰强制加深为 `#333`。 |
| 06 | 第二重 | 自动扫描所有带 `style="..."` 但漏写 `color:` 的 `div` / `table` / `section` / `p` / `h1` / `h2` / `small` 标签并补齐显式 `color`（标题 `#111`、正文容器/表格 `#222`、辅助标签 `#333`），从机制上杜绝未来新增代码漏写 `color`。 |
| 07 | 要点说明 | **保持单条消息「一页推」体积余量**： |
| 08 | 要点说明 | 将日历星级、逐栏 `⌁ AI 研判` 与 `🦑 鲜鲜解读` 的冗余 `<span style="color:...;font-weight:900;">` 精简为 `<b style="color:...">`，移除 `octopus_quant/render.py` 个股代码的冗余无色 `<span>`，在为全部 205 个容器/表格补齐显式 `color` 后，重度日全量报告仍控制在 `92,687` 字符（含周度预测 `94,723` 字符 < `95,000` 门禁，`output/latest.html` `98,579` 字符 < `100,000` 上限）。 |
| 09 | 要点说明 | **修复 GitHub Actions `git add` 因缺失可选留痕文件而漏提交 `output/latest.html` 的问题**： |
| 10 | 要点说明 | 初始化 `output/hk7_forecast.json` 与 `output/weekly_forecast.json`，并在 `output/pipeline.py` 主流程落盘阶段确保工作流 `git add` 列表中的可选留痕文件始终存在，防止未配置 `OCTOPUS_LLM_API_KEY` 时因文件不存在触发 `git add` 退出码 128 而漏提交最新日报。 |
| 11 | 要点说明 | **新增单元测试门禁 `test_every_text_node_has_explicit_color_without_body_tag`**： |
| 12 | 要点说明 | 在 `tests/test_pipeline.py` 中模拟 PushPlus `v-html` 剥离 `<body>` 后的 DOM 树，逐一校验全篇日报、精简兜底版及落盘 HTML 文件中的每一个可见文本节点，强制要求 `unstyled == []`（剥离 `<body>` 后未声明 `color` 的文本节点数为 **0**）。 |
