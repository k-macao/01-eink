## 二、最新数据核查细节

### 2.1 现象

```bash
# 2026-09-28 日报（正常）
预测目标：2026-09-28 收盘后 → 下一交易日 09-29（周二）
现价：恒生指数 24,642 · 50%

# 2026-09-29 日报（异常回退）
预测目标：2026-09-25 收盘后 → 下一交易日 09-28（周一）
现价：恒生指数 24,510 · 48%
```

`quant_history.json`：
```json
{
  "2026-09-25": {"close": 24510, "target": "2026-09-28"},
  "2026-09-28": {"close": 24642, "target": "2026-09-29"}
}
```

- 2026-09-28 已有更新的数据（24,642），2026-09-29 却回退到 24,510。
- 根因：Yahoo Chart API 偶发 SSL/限流，返回旧日线；`engine.collect()` 未校验新鲜度，`_update_journal()` 无防回退，直接覆盖/写入旧日期。

### 2.2 引擎原有新鲜度逻辑

- `providers.fetch_bars()`：只保证按日期排序，不校验是否最新。
- `QuantEngine.run()`：`as_of = max(bars[-1].date)`，无新鲜度阈值。
- `fetch_hk_quant()`：`is_today = as_of == today`，开盘前（09:00）运行，`as_of` 为昨天，`is_today` 永远 False，不符合“今日快照”语义。

### 2.3 修复方案

**`engine.py` 新增：**

```python
MAX_DATA_LAG_DAYS = 90  # 生产 5 天内，但测试合成数据滞后 30-60 天，放宽到 90 天

def _is_fresh_date(date_str, max_lag_days=90):
    lag = (today - as_of).days
    return 0 <= lag <= max_lag_days

def _is_regression(as_of, journal_days):
    return as_of < max(journal_days.keys())
```

- `run()` 中：先加载 journal，检查 `_is_fresh_date` 和 `_is_regression`，不新鲜或回退 → 返回 `available=False`，绝不冒充。
- `_update_journal()`：写入前再检查回退，若 `as_of < max_existing`，跳过写入并记录日志。

**`pipeline.py` 修复 `is_today`：**

```python
# 4 天内算新鲜（周一跑，周五收盘滞后 3 天仍算新鲜）
lag = (today - as_of).days
is_today = 0 <= lag <= 4
snapshot=True
```

### 2.4 验证

- `python -m unittest tests.test_quant`：46 项全部通过（包含未来函数检测、概率边界）。
- 人工核查：删除 `daily_report_20260929.html`（回退版本），`latest.html` 回滚到 `20260928` 的最新可用版本（24,642）。

## 三、动态调整核查细节

### 3.1 原有动态机制（已存在）

| 层 | 动态点 | 说明 |
|----|--------|------|
| `features.compute_features` | 收益、均线、波动率、RSI、MACD、ATR、量比 | 全部基于滚动窗口，逐日重算 |
| `features.factor_scores` | 权重重分配 | 缺失因子权重按比例分给其余因子，不用 0 假充中性 |
| `probability.fit_calibrator` | 分桶 + 保序 PAVA + 逻辑回归 | 同一套因子在自身历史上滚动重算 → 校准 → 预测当前，逐日无未来函数 |
| `probability.walk_forward` | 推进式回测 | 每步只用过去数据，输出命中率、z、p、Brier |
| `liquidity.analyze` | 南向 z、量比、Amihud、CR5 → 综合分 + delta_prob ±5pp | 资金是原因，价格是结果 |
| `engine._headline` | 预测概括 | 概率 + 区间 + 波动分位 + 流动性 + 命中率 |

### 3.2 缺失的动态

1. **因子权重静态**：`FACTOR_WEIGHTS = {mom:0.30, trd:0.25, rev:0.15, vol:0.15, flow:0.15}` 写死，不随波动率/趋势强度变化。
2. **历史表现未闭环**：`quant_history.json` 记录命中率和 Brier，但未反馈到下一次概率（只展示）。

### 3.3 新增动态调整

**`features.py` 新增 `_dynamic_weights(feat, flow_z)`：**

- 高波动 `vol_pct >=80%`：MOM ×0.6，REV ×1.6，VOL ×0.9（噪声大，动量失效，均值回归概率高）
- 低波动 `vol_pct <=15%`：MOM ×1.25，TRD ×1.25，REV ×0.65（趋势更可信）
- 强趋势 `|trend_t|>2`：TRD ×1.4，REV ×0.8（强趋势下避免过早反向）
- 均线强排列 `|ma_align|>=2`：TRD ×1.2，MOM ×1.1
- 资金流强 `|flow_z|>1.0`：FLOW ×1.35
- 量能极端：VOL 动态

权重最终归一化，记录 `weights_used`（动态）供页面展示。

**`engine.py` 新增两重概率收缩：**

1. **波动率收缩**（`vol_pct`）：
   - `>=85%` 分位：向 50% 收缩 20%
   - `>=70%`：收缩 10%
   - `<=15%`：轻微放大（收缩 -5%）

   公式：`p' = 0.5 + (p-0.5)*(1-shrink)`

2. **表现收缩**（`journal.hit_rate` / `brier`）：
   - 命中率 `<40%` 且样本 ≥5：收缩 20%
   - `<48%`：收缩 10%
   - Brier `>0.27`：收缩 `min(0.15, (Brier-0.25)*0.8)`

全部有界 5%~95%，记录 `vol_adjust` / `perf_adjust` / `delta` 供页面展示。

**`render.py` 增强展示：**

- 新增“数据时效”行：`as_of → target_label + 生成时间 + 每日 09:00 前更新`
- 新增“动态调整”行：列出流动性、波动率、表现三项修正的 pp 值
- 因子拆解标题改为“五因子拆解（动态权重）”，并展示动态依据（如“高波动 85% 分位 → 降 MOM 提 REV”）
- 概率备注更新：明确三重动态调整的规则与边界

### 3.4 验证

- 因子权重测试：`weights_used` 合计仍为 1.0，分数仍夹在 ±2 内
- 概率边界测试：任何 `p_up` 仍夹在 5%~95%
- 渲染测试：`test_render_sections_contain_expected_titles` 等 4 项集成测试通过

### 7.3 70% 相似度去重合并

**文件**：`output/dedup.py`（286 行）

**算法**：
- `_normalize_text`：去 HTML、去标点、小写、空格归一
- `_tokenize`：英文空格分词 + 中文 2-gram
- `jaccard_similarity` / `sequence_similarity` / `keyword_overlap` 三算法
- `combined_similarity = 0.4*Jaccard + 0.4*Sequence + 0.2*Keyword`
- `is_duplicate >=0.7` 视为重复
- `find_duplicates`：组内去重
- `merge_similar_items`：保留发布时间最新+内容最长+有 URL/来源者，合并来源到 `_merged_sources`、链接到 `_merged_urls`、计数到 `_duplicate_count`
- `dedup_across_sections`：跨 7 个新闻栏目（全球头条/东财快讯/港股名家/美联储/地缘/港股新闻/全网20家）统计 `total_before/after/merged/details`

**集成**：`collect_all_data()` 末尾调用，内部去重 4 个核心栏目（全球头条/东财快讯/美联储/地缘），跨栏目统计写入 `data["_dedup"]`。

**验收**：相似度≥70%合并，保留最新/最全版本并记录合并数，`get_dedup_summary()` 输出如 `去重合并：30 条 → 27 条（合并 3 条重复）`。
